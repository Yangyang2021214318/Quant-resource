2.1 问题简化：从小规模案例发现规律

English idea
When the original problem is too complex, begin with a simplified version. Solve the smallest cases, look for a pattern, and gradually increase the complexity.
中文理解
当原问题过于复杂、无法立即求解时，先把规模降下来。先解决最小案例，再逐步增加参与者或状态数量，观察规律是否稳定出现。
核心方法
复杂问题 → 最小规模 → 递推观察 → 识别不变量 → 推广到一般规模 → 检查边界条件

题型一：Screw Pirates · 海盗分金币

题目概述

若干名海盗按资历依次提出金币分配方案。方案需要获得至少一半票数，否则提案者会被淘汰，流程交给下一名海盗。所有海盗都足够理性，优先保证自己存活，其次希望获得更多金币；若收益相同，还倾向于让更少的人分到金币。

这里保留题型和条件的学习摘要，不复刻原题全文。

第一步：从 1 名海盗开始

只有一名海盗时，不存在投票冲突，他可以拿走全部金币。这个案例提供递推的起点。

第二步：逐步增加人数

人数关键结果推理重点
1提案者保留全部无需他人支持
2提案者只需买下一票分析失败后下一轮谁会得到什么
3向上一轮会被淘汰、收益最低的人购买支持用最少金币获得必要票数
5继续逆向推理，提案者购买关键票票数约束与生存优先级共同决定方案

通用解题框架

  1. 从最小规模开始列出结果。
  2. 假设人数为 (n-1) 时的方案已知。
  3. 分析当前提案失败后，每个投票者在下一轮的收益。
  4. 提案者只给“下一轮收益最低”的必要支持者略高于其保留收益。
  5. 剩余金币全部留给自己。
面试中要说清楚的关键点：
这不是简单平均分配，而是一个逆向归纳问题。支持票的价格由“如果当前提案失败，我下一轮能得到什么”决定；因此必须先求下一轮结果，再回到当前轮。

数学抽象

设当前有 (n) 人，提案者需要 (q) 票支持（是否包含自己要根据题目规则确认）。对每个其他海盗 (i)，计算其在失败后的收益 (v_i)。若当前给他 (v_i+1) 枚金币即可获得支持，则选择这些成本最低的海盗，直到达到票数要求。

常见错误

  • 没有先算“提案失败后”的下一轮分配。
  • 忘记确认“至少一半”是严格多数还是过半数。
  • 默认所有人只追求金币，忽略题目给出的生存优先级。
  • 直接猜最终分配，没有列出小规模案例。

题型二：Tiger and Sheep · 老虎与羊

题目概述

岛上有若干只老虎和一只羊。老虎可以吃草，但更愿意吃羊；每次只有一只老虎能吃羊，而且吃羊的老虎会变成羊。所有老虎都理性并希望生存。问题是：羊最终是否会被吃掉？

关键简化

不要直接分析很大的老虎数量。先比较 (n=1,2,3,4) 等小规模情形，观察“吃羊后剩下多少只老虎”是否改变下一步的激励。

老虎数量吃羊后的结构激励判断
1老虎变成羊，没有其他老虎会吃
2吃羊者变羊，另一只老虎可以吃它不会吃
3吃羊后形成 2 只老虎与 1 只羊的结构会吃
4吃羊后形成 3 只老虎与 1 只羊的结构不会吃

规律与证明

设 (S(n)) 表示有 (n) 只老虎时羊是否会被吃。若某只老虎吃羊，它会变成羊；剩余 (n-1) 只老虎会面对一个类似问题。因此，当前老虎比较的是：

  • 不吃：自己继续作为老虎生存；
  • 吃：自己变成羊，并将面对剩余老虎对新羊的行为。

小规模结果呈现交替结构：奇偶性改变了吃羊后的后续局面。面试时应说明这是由递推关系产生的，而不是凭直觉猜奇偶。

解题重点：
把“动物故事”转成状态 (S(n))，再比较行动后的状态。每次行动都会把问题规模从 (n) 降到 (n-1)，因此可以用数学归纳法或逆向递推分析。

Python 验证递推结构

def sheep_eaten(n):
    """教学用递推：1 只时会吃，之后交替变化。"""
    if n == 1:
        return True
    return not sheep_eaten(n - 1)

for n in range(1, 11):
    print(n, sheep_eaten(n))
